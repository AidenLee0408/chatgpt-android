개요

페르소나 허브(가칭)는 개인이 자신의 정보를 여러 페르소나로 나눠 한 곳에 저장하고,
ChatGPT·Claude·Gemini가 MCP 커넥터로 필요한 페르소나만 읽어가게 하는 모바일 서비스다. 사용
자는 AI마다 자기소개를 반복 입력하지 않고, 어떤 AI가 어떤 정보를 보는지 직접 통제한다.

타깃: 여러 AI 어시스턴트를 번갈아 쓰는 개인(직장인, 프리랜서, 대학원생). B2B는 범위 밖.
이번 문서 범위: MVP부터 v2까지의 기능 요구사항, 그리고 MVP 기준 시스템 아키텍처.
범위 밖: 팀·기업용 기능, 자체 AI 챗봇, 결제 연동 상세.

기능명세서 1 — 목표, 사용자, 시나리오
MVP의 성공 기준은 "가입 후 10분 안에 페르소나 1개를 만들고 AI 1개에 연결해, 그 AI가 첫 대화에서 나
를 알아보는 것"이다.

사용자 페르소나

멀티 AI 직장인 (주 타깃): 업무에는 Claude, 일상에는 ChatGPT, 구글 워크스페이스 작업에는
Gemini를 쓴다. 회사 정보와 개인 정보가 섞이는 게 싫다.
프리랜서: 클라이언트별로 다른 맥락이 필요하다. 클라이언트 A의 정보가 B 작업에 새어 나가면 안 된
다.
건강·재무 관리형 개인: 복용 약, 알레르기, 투자 성향처럼 민감한 정보를 AI 상담에 쓰고 싶지만, 아무
AI에나 주고 싶지는 않다.

핵심 사용자 시나리오

1. 온보딩: 사용자가 앱을 설치하고 가입한다. 템플릿(업무/개인/건강)에서 하나를 골라, 질문 5~7개에

답하면 페르소나가 만들어진다.

2. AI 연결: 앱이 연결 가이드를 보여준다. 사용자는 Claude나 ChatGPT 설정에서 우리 MCP URL을

추가하고, OAuth 동의 화면에서 이 AI가 볼 페르소나를 고른다.

3. 일상 사용: 사용자가 Claude 모바일 앱에서 "이번 주 발표 자료 구성 도와줘"라고 쓴다. Claude가 업

무 페르소나를 조회해 직무·회사 도메인·선호 톤을 반영해 답한다.

4. 정보 갱신: 대화 중 AI가 "새 직장 정보를 저장할까요?"라고 제안하면, 제안은 앱의 검수함으로 들어간

다. 사용자가 승인해야 팩트가 바뀐다.

5. 통제: 사용자가 앱에서 "어떤 AI가 언제 무엇을 읽었나" 로그를 보고, 필요하면 연결을 끊거나 범위를

줄인다.

6. 폴백: 커넥터를 쓸 수 없는 무료 플랜 AI에서는 앱의 "복사" 버튼이나 키보드 확장으로 컨텍스트 팩을

대화창에 붙여넣는다.

기능명세서 2 — 기능 목록과 상세 요구사항

MVP는 9개 기능으로, "페르소나를 만들고 → 범위를 정해 → Claude·ChatGPT에 연결하고 → 누가 읽
었는지 본다"까지만 한다. AI가 정보를 쓰는 기능과 Gemini 연결은 v1로 미룬다.

MVP 상세 요구사항과 수용 기준

F-02 페르소나 관리

사용자는 페르소나를 최대 10개까지 만든다(무료 3개).
페르소나는 이름, 아이콘, 한 줄 설명, 팩트 목록, 선호 지시문("답변은 존댓말, 결론 먼저")을 가진다.
팩트는 카테고리(신상·직업·관심사·건강·재무·선호·기타), 본문(최대 500자), 민감도, 출처(직접 입
력/인터뷰/AI 제안), 수정 시각을 가진다.
수용 기준: 팩트 수정 후 3초 안에 MCP 조회 결과에 반영된다. 삭제한 팩트는 어떤 경로로도 조회되지
않는다.

F-03 인터뷰형 온보딩

템플릿 3종(업무/개인 생활/건강)으로 시작한다. 템플릿마다 질문 5~7개.
서버의 LLM이 답변을 팩트 단위로 쪼개고 카테고리·민감도를 추천한다. 사용자가 확인 후 저장한다.
수용 기준: 질문에 모두 답하면 3분 안에 팩트 10개 이상의 페르소나가 만들어진다. 추천된 민감도는
저장 전 반드시 사용자에게 보인다.

F-05 MCP 커넥터

원격 MCP 서버(Streamable HTTP)와 OAuth 2.1을 제공해, 사용자가 URL 하나로
Claude·ChatGPT에 추가할 수 있게 한다.
도구는 읽기 전용으로 시작한다: 페르소나 목록, 페르소나 조회, 팩트 검색.
수용 기준: Claude와 ChatGPT 웹·모바일에서 연결 후 "내 업무 페르소나 알려줘"에 올바른 내용이
나온다. p95 응답 500ms 이하.

F-06 연결별 범위 동의

OAuth 동의 화면에서 사용자가 이 연결에 허용할 페르소나와 최대 민감도를 고른다. 기본값은 "일반
등급만".
앱의 연결 상세 화면에서 언제든 범위를 바꾸거나 연결을 끊는다. 끊으면 토큰이 즉시 폐기된다.
수용 기준: 범위 밖 페르소나는 목록 조회에서도 존재 자체가 드러나지 않는다.

F-07 접근 로그

모든 MCP 호출을 연결·도구·반환된 팩트 ID·시각 단위로 기록한다. 앱에서 연결별, 날짜별로 본다.
수용 기준: 조회 후 10초 안에 로그에 보인다. 로그는 1년 보관 후 삭제.

F-08 컨텍스트 팩 복사

페르소나 하나 이상을 골라 AI에 붙여넣기 좋은 텍스트(한국어/영어)로 만든다. 길이 옵션: 짧게(300
자)/보통/자세히.
민감 등급 팩트는 기본 제외, 체크해야 포함.

F-09 내보내기·탈퇴

전체 데이터를 JSON으로 내려받는다. 탈퇴 시 즉시 모든 연결 토큰을 폐기하고, 데이터는 30일 안에
백업까지 파기한다.

기능명세서 3 — 화면 구성, 권한 정책, 비기능 요구사항
앱은 하단 탭 4개(페르소나 · 연결 · 활동 · 설정)로 구성하고, 모든 권한 판단은 "민감도 등급 × 연결별 범
위" 두 축으로 한다.

기술 아키텍처 1 — 시스템 구성과 기술 스택
진입점은 셋(앱 API, OAuth, MCP)이지만 데이터를 읽는 길은 코어 서비스 하나뿐이다. 권한 필터를 한
곳에만 두어야 "범위 밖 정보가 새는" 버그를 구조적으로 막을 수 있다.

시스템 구성 · 클라이언트 2종, 서버 3종, 코어 1개, 인프라 4종

앱은 사용자 본인 권한으로, AI 클라이언트는 연결별로 좁혀진 OAuth 토큰으로 들어오며, 둘 다 코어 서
비스에서 같은 필터를 통과한다.

다. 프롬프트로 막지 않는다.

인증 흐름(OAuth 2.1 + PKCE)

1. 사용자가 Claude·ChatGPT 설정에 MCP URL을 붙여넣는다.
2. AI 클라이언트가 MCP 서버를 호출하고 401과 함께 보호 리소스 메타데이터 위치를 받는다.
3. 클라이언트가 인가 서버 메타데이터를 읽고, 동적 클라이언트 등록(DCR)으로 client_id를 받는다.
4. 클라이언트가 PKCE와 함께 인가 요청을 보내면, 사용자 브라우저에 우리 로그인·동의 화면이 뜬다.
5. 사용자가 로그인하고 이 연결에 허용할 페르소나와 최대 민감도를 고른다. 이때 connections 행이

만들어진다.

6. 인가 코드가 토큰으로 교환된다. 액세스 토큰 1시간, 리프레시 토큰 30일(회전).
7. 이후 모든 MCP 호출은 Bearer 토큰 → connection 조회 → 코어 필터 → 응답 순으로 처리된다.
8. 사용자가 앱에서 연결을 끊으면 리프레시 토큰을 폐기하고 connection을 revoked로 바꾼다. 남은

액세스 토큰도 다음 호출에서 거절된다.

모바일 앱 로그인은 이 흐름과 분리해 소셜 로그인 + 자체 JWT로 처리한다. 동의 화면은 웹이므로 같은
계정 세션을 웹에서도 쓸 수 있게 한다.

기술 아키텍처 3 — 보안, 개인정보, 인프라
이 서비스의 제품 가치는 곧 보안이다. 원칙은 세 가지다: 받지 않아도 되는 정보는 받지 않는다, 서버가 필
터한다, 사용자가 모든 접근을 볼 수 있다.
